## 2. 活動類型

| 類型 `kind` | 參數 | 例 |
|---|---|---|
| `PERCENT_OFF` | `discount_pct`（1–99） | 全館九折 |
| `FIXED_PRICE` | `price`（含稅整數元 > 0） | 這款營燈特價 990 |
| `AMOUNT_OFF` | `amount`（含稅整數元 > 0） | 每件折 100 |
| `BUY_N_GET_M` | `buy_qty` N ≥ 1、`free_qty` M ≥ 1 | 買五送一 |
| `BUNDLE` | 組合格子（§4）＋`bundle_price` | 帳篷＋椅子＋桌子 8,888 |

共同欄位：`name`、`starts_at`/`ends_at`、`status`（DRAFT/ACTIVE/ENDED/CANCELLED，狀態機同 docs/21）、
`stackable`（可與其他活動疊加，預設 false）、`store_id`、稽核欄位。
**拿掉「同店至多一個 ACTIVE」的 DB 約束**；同時生效的活動數不設上限。

## 3. 適用範圍（`campaign_targets`）

每個活動有一組「包含」條件與一組「排除」條件；品項符合任一包含、且不符合任何排除，才算適用。
沒有任何包含條件＝全部（仍受品項種類與排除限制）。

| `target_type` | `target_id` 指向 | 備註 |
|---|---|---|
| `ITEM_KIND` | 自有序號／寄售序號／散裝／一般商品 | 沿用 docs/21 的四個開關，改存成條件 |
| `CATEGORY` | categories | |
| `BRAND` | brands | |
| `PRODUCT_MODEL` | product_models | 二手最實用的粒度：同型號多件 |
| `SERIALIZED_ITEM` | serialized_items | 單一件 |
| `CATALOG_PRODUCT` | catalog_products | |
| `BULK_BASKET` | bulk_baskets | 販售籃（ADR-025） |

- 餐飲（MENU）永不參加（沿用裁示）。
- 寄售序號品：打折／特價／折金額只在明確包含 `ITEM_KIND=寄售` 時才適用（即 docs/21 的
  `applies_consignment`），且寄售人按折後分潤；**買 N 送 M、組合包一律排除寄售**（裁示 7）。
- 一律驗證 target 屬本店（跨店＝404）。

## 4. 組合包格子（`bundle_slots`）

一個 `BUNDLE` 活動有 ≥ 2 個格子；每格＝一組範圍條件（同 §3，通常是 `PRODUCT_MODEL`／`CATEGORY`／
`CATALOG_PRODUCT`）＋`qty`。購物車裡能湊出每一格所需件數，就成一組；可湊多組。
組合價以「組內各件原價」比例分攤到各行（HALF_UP，尾差給最後一行，保證 Σ＝組合價）。

## 5. 定價：整車一次算（純函式 `campaigns/pricing.py`）

現行 docs/21 是逐行套折後單價。買 N 送 M 與組合包需要跨行計算，改為**結帳／報價先把整台購物車交給
一支純函式**，算出每行的活動折讓，再逐行寫入。報價、結帳、客顯、收據共用同一支，口徑不漂移。

輸入：各行（原含稅單價、數量、品項屬性：種類／分類／品牌／型號／id／是否寄售）、生效活動、
店員的選擇（取消哪些活動、買 N 送 M 指定送哪件）。輸出：每行的活動折讓總額與明細
`[(campaign_id, amount)]`、組合包分組。

**計算順序**（固定）：

1. **組合包**（僅不可疊加以外的特例見 3）：窮舉可湊成的組，**只在比該些品項走第 2 步更划算時才成組**
   （裁示 1：對客人最划算）。成組的品項不再參加第 2、3 步的不可疊加活動。
2. **單件活動**（打折／特價／折金額）：候選＝每個「不可疊加」活動**單用**各算一個價、以及
   「可疊加」活動**全部連乘**算一個價（依活動 id；打折乘比例、折金額直接減、特價取較低者；
   裁示 2、9），取單價最低者；同價偏好 id 較小的不可疊加活動，最後才是疊加組合。
   每套一個活動四捨五入一次，各活動分到的折讓都是整數元、加總＝總折讓。
   任何時候單價不低於 1 元（0 元＝贈品，走贈品流程，docs/32 紅線）。
   實作：`backend/app/modules/campaigns/pricing.py`（純函式）。
3. **買 N 送 M**：把適用的件依第 2 步後的單價展開、由高到低排，每 N+M 件一組，組內最便宜的 M 件免費；
   店員可指定別件（裁示 4，P3b）。免費額**按組內各件價格比例分攤**到這 N+M 件（裁示 3），不是 0 元明細。
   P3a 實作定案（依裁示 1、9 推得）：
   - **可疊加**的買 N 送 M：疊在第 2 步後的價格上；第 2 步用了「不可疊加」活動的件不參加（不可疊加＝不跟任何活動併用）。
   - **不可疊加**的買 N 送 M：以原價成組、不跟任何活動併用；只有整體比第 2 步便宜才採用（對客人最划算），
     否則那些件維持第 2 步的價格。比較以「成組的那些件」為單位。
   - 每件只參加一個買 N 送 M（依活動 id 先到先得）；湊不滿一組的件維持第 2 步價格。
   - 寄售品一律不參加（裁示 7）；管理頁選「買幾送幾」時不提供寄售選項，DB CHECK 也擋。
   - 分攤時每件至少付 1 元；分不下的折讓捨去（只會發生在 1 元商品這種極端情況）。
   - **店員改指定（P3b）**：購物車行帶 `promo_free=true`＝「送這件」。在組內就跟該組預設送的那件對調；
     沒湊進組的就換掉最後一組送的那件（被換下的改原價）。送的位置有限（每組 M 件），指定超過的依排序
     取前面的；不在活動內或沒成組的指定不生效，POS 會註明。生效的寫 audit_log
     `SALE_BNGM_FREE_ITEM_CHOSEN`（活動 id、第幾行），不需主管核准（裁示 8）。
     欄位跟著購物車行走（結帳、客顯購物車、還原、補單都自動帶到），沒勾時不進冪等指紋。
   - 同一行數量 > 1 時各件可能分到不同折讓：`line_total` 為準，`unit_price` 存平均四捨五入
     （發票以 net_amount ÷ qty 上送、退貨依 net_amount 按數量比例，都不讀 unit_price × qty）。
4. **臨時折扣**（docs/32）照舊接在活動之後：單品 → 整單。

每一步都是 Decimal、整數元、HALF_UP；分攤用最大餘數法保證加總不差一元。

## 6. 資料模型（Alembic）

- **沿用 `campaigns` 表、不改名**（P1a 定案）：拿掉「同店至多一個 ACTIVE」、加 `stackable`；
  §3 的「品項種類」沿用既有四個 `applies_*` 開關，不另存成條件。P2 起加 `kind` 與各類型參數。
- `campaign_targets`（campaign_id, mode=INCLUDE|EXCLUDE, target_type, target_id, store_id）。
- `bundle_slots`（campaign_id, slot_no, qty）＋`bundle_slot_targets`（同 targets 結構）。
- `sale_line_campaigns`（sale_line_id, campaign_id, discount_amount, store_id）：一行可有多筆；
  `sale_lines.discount_amount` 仍為本行活動折讓總額（＝Σ）；`sale_lines.campaign_id` 留
  「貢獻最多的活動」供舊畫面相容。migration 以舊單的 `campaign_id`＋`discount_amount` 回填。
- `sale_bundle_groups`（id, sale_id, campaign_id, bundle_price）＋`sale_lines.bundle_group_id`。
- `sale_campaign_overrides`（sale_id, campaign_id, reason 可空；P3 起加 action=FREE_ITEM 與 sale_line_id）：
  店員取消套用或改指定送哪件的留痕（裁示 8、10：不需核准、原因可不填，寫 audit_log）。**P1c 才建**。
- `sale_lines.unit_price` 語意維持「本行成交單價」；分攤後不整除時存**本行平均單價四捨五入**，
  `line_total` 為真正的活動折後小計（`unit_price × qty` 可能差 < qty 元，退貨／發票一律用 `net_amount`）。
  ——此點會影響既有「line_total = unit_price × qty」的假設，實作前先盤點所有讀取點。

## 7. POS 與客顯

- 購物車每行顯示套到的活動名稱與折讓；組合包以框線群組並標「組合價」；買 N 送 M 標出哪件免費
  （可點「改送這件」）。
- 購物車上方列出本筆套到的所有活動，每個旁邊有「這筆不套用」（需選原因）；取消後即時重算。
- 客顯同步顯示活動名稱與折讓（客人看得到為什麼便宜）。
- 冪等指紋納入「取消的活動」與「指定送哪件」。

## 8. 退貨

- 一般活動折讓：沿用退實付（`net_amount` 按數量比例）。
- 買 N 送 M：各件實付已含分攤，退一件退它的分攤後實付；**不回推**剩下各件的價格。
- 組合包：**整組退**（裁示 5）——退貨請求必須包含該組全部明細與全部數量，否則 422。
- 寄售品：沿用 settlement 反轉。

## 9. 報表

活動成效改以 `sale_line_campaigns` 彙總：每個活動的折讓總額、帶動營業額、筆數；組合包另列售出組數。
臨時折扣、贈品報表口徑不變。

## 11. 不變量（以測試守護）

1. 每行 `net_amount ≥ 1`（一般行），Σ行活動折讓＝Σ`sale_line_campaigns`。
2. 分攤加總不差一元；稅仍於發票總額層級推一次（`net + tax = total`）。
3. 不可疊加的活動每件至多套一個、且不與任何活動併用；可疊加者連乘；每件取單價最低的候選。
4. 報價與結帳對同一購物車、同一時間點算出相同金額。
5. 寄售品不進買 N 送 M／組合包；打折時寄售人按折後分潤。
6. 組合包只能整組退。
7. 取消套用／改指定都寫 audit_log，且進冪等指紋。
