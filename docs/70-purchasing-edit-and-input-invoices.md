# 70 — 採購單事後修改＋進項發票獨立登錄

> 2026-10-08 店主回報與裁示。決策紀錄見 `adr/ADR-030-purchase-order-edit-and-input-invoices.md`。

## 1. 店主回報

1. 採購單品項多時「無法捲動」。
2. 品項打錯就不能改。
3. 已確認（下單）、已收貨的採購單不能再改。
4. 收貨後廠商常**隔月**才開發票，事後要能登錄、更正。

## 2. 裁示（2026-10-08）

| 問題 | 裁示 |
|------|------|
| 已收貨品項改數量／換商品，庫存怎麼辦 | **自動調整庫存**：差額加減並留異動帳；已賣掉、不夠扣就擋下並說明 |
| 已收貨品項改進價，商品成本 | 這張單是該商品**最近一次進貨**才同步商品成本；已賣出的成本不追溯 |
| 誰能改 | 草稿：大家都能改；**已下單／部分到貨／已收貨：只有管理者**，每次修改寫稽核（前後值） |
| 哪些打錯要能改 | 選錯商品、數量或進價填錯、商品名稱錯字、多加或漏加品項（四種都要） |
| 一張發票對幾批收貨 | **都有可能**：一批一張，或整月合併一張涵蓋多批收貨（可跨採購單） |

## 3. 捲動（問題 1）

- 收貨對話框固定在畫面中央、沒有高度上限：品項一多，確認鈕超出畫面、按不到。→ 對話框限高、內部捲動。
- 明細頁殘留以前當彈窗時的 `max-height: 88vh` 內捲，變成框中框、表頭被捲走。→ 拿掉，整頁自然捲動。

## 4. 採購單修改（問題 2、3）

### 4.1 操作

明細頁「修改」→ 獨立的修改頁（與建立頁同一個表單）：可換供應商、改數量／進價、移除品項、加品項（搜既有或新增商品）。
部分到貨／已收貨的單多一欄「已收」可改。品名錯字在修改頁該列按「改名」直接改商品名稱（沿用商品改名，管理者）。
「選錯商品」＝移除錯的那列、加對的商品並填已收數量——效果與「換商品」相同，不另做換商品按鈕。

### 4.2 API

`PUT /api/v1/purchase-orders/{id}`（`updatePurchaseOrder`）：整張覆寫 `{supplier_id, lines: [{id?, catalog_product_id, qty, received_qty, unit_cost}]}`。
有 `id` 的列＝改既有明細；沒有的＝新增；原有但沒帶的＝刪除。整張覆寫天然冪等（重送同內容差額為 0）。

### 4.3 規則

- 取消的單不能改。草稿與已下單：`received_qty` 必須為 0（還沒收過貨）。
- 部分到貨／已收貨：每列 `0 ≤ received_qty ≤ qty`。改完重算狀態：全部收足 → RECEIVED（`received_at` 沒有就補當下）；否則 PARTIAL。
- 同一張單同一商品只能一列；至少一列；數量、進價正整數（與建立相同）。
- 換供應商：新供應商須啟用中；已有收貨掛在**別家供應商**的進項發票上就擋（先改發票）。供應商名快照跟著換。
- 權限：非草稿只有管理者（403）。

### 4.4 庫存

以「商品 → 已收總數」比對改前改後，逐商品差額：
- 增加 → 加庫存、寫 `IN / PURCHASE_CORRECTION` 異動；
- 減少 → 原子扣庫存（不足則整筆擋下：「『X』現在只剩 N 件，收貨數不能少 M 件（可能已賣出）」）、寫 `OUT / PURCHASE_CORRECTION`。
- 異動 `ref_type = "purchase_order"`、`ref_id = 採購單 id`。庫存明細顯示「進貨更正」。

### 4.5 成本

受影響的商品（收貨數或進價有變、或換掉的）：改前或改後「最近一次進貨」是這張單，就把商品成本設為改後最近一次進貨的進價
（「最近」＝採購單最後一批收貨時間，再以單號）。都不是就不動。已成交明細存有成本快照，不受影響。

### 4.6 稽核

`UPDATE_PURCHASE_ORDER`：前後值含狀態、供應商、全部明細（商品、數量、已收、進價）。

## 5. 進項發票獨立（問題 4）

### 5.1 資料

新表 `purchase_input_invoices`：店、供應商、供應商名快照、發票號碼（2 英文＋8 數字）、發票日期、未稅、稅額、含稅
（`未稅＋稅額＝含稅`）、登錄人。同店同號同日唯一（沿用原規則）。
`goods_receipts.input_invoice_id` 指向發票（可空）——**一批收貨最多掛一張發票，一張發票可掛多批**（可跨採購單，須同一供應商）。
原本 `goods_receipts` 上的五個發票欄位搬進新表後移除（migration 逐筆搬、連結；降版只在每張發票恰好一批時可還原，否則拒絕）。

### 5.2 API

| 端點 | operation_id | 權限 |
|------|--------------|------|
| `GET /purchase-input-invoices` | `listInputInvoices`（可依供應商、分頁） | 全員 |
| `GET /purchase-input-invoices/count` | `countInputInvoices` | 全員 |
| `GET /purchase-input-invoices/{id}` | `getInputInvoice` | 全員 |
| `POST /purchase-input-invoices` | `createInputInvoice` | 全員（收貨的人當下就能登） |
| `PUT /purchase-input-invoices/{id}` | `updateInputInvoice` | 管理者，寫稽核 |
| `DELETE /purchase-input-invoices/{id}` | `deleteInputInvoice` | 管理者，寫稽核；所掛收貨回到「待開發票」 |
| `GET /suppliers/{id}/uninvoiced-receipts` | `listUninvoicedReceipts` | 全員 |

建立／修改都帶 `receipt_ids`（至少一批）：每批須屬同一供應商、未掛別張發票（修改時可保留自己原有的）。
收貨對話框仍可當下填發票：建一張只掛這一批的發票（同一交易）。原「補登發票」端點移除，改由發票頁處理。

### 5.3 畫面

採購頁新增「進項發票」分頁：清單（號碼、日期、供應商、含稅、涵蓋幾批）＋「登錄發票」。
登錄／修改：選供應商 → 列出該供應商**還沒開發票的收貨**（採購單號、收貨日、這批金額）勾選 → 填號碼、日期、三金額；
畫面提示「勾選的收貨合計 $X、發票含稅 $Y」，不一致只提醒不擋（運費、折扣、尾差都可能）。
採購單明細的每批收貨顯示掛的發票（連到發票），沒有就顯示「尚未開發票」與「登錄發票」連結（帶入這批）。

### 5.4 報表

申報月報的進項清單改以發票為單位（依發票日期歸期，同原口徑），參照欄列出涵蓋的採購單號。

## 6. Codex 對抗審查（店主裁示）

- 第一輪：①存過再打開修改會帶出舊數量、再存就把庫存改回去 → **已修**：修改頁一律等拿到伺服器最新的採購單才帶入，
  快取只放商品資料。
- **已知風險（店主裁示不修，店內單台電腦、要同一瞬間兩邊操作才會遇到）**：②改某商品進價時另一張單同時收同一商品，
  商品成本可能被蓋成較舊的進價；③登錄發票的同時有人把那張採購單換供應商，發票可能掛到別家的收貨。

## 7. 不做

- 一批收貨拆在兩張發票上（極少見；需要時把整批掛在其中一張、金額照發票填）。
- 已售出部分的成本追溯。
