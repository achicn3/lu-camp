# ADR-033：寄售帳篷由 POS 維護，經線上點餐雲端推上官網

- 狀態：已採納（店主八項裁示 2026-10-30；規格見 docs/97）
- 相關：ADR-027（線上點餐放 Cloudflare、雲端不連進店內）、docs/63 §13（線上零售商品）

## 背景

官網（lukeng-camp.com，獨立 repo `~/lukeng-homepage`，Cloudflare 靜態網站）要新增「寄售帳篷」頁。
店主要求由店長、店員在 POS 維護，自動同步到官網。POS 在店內 MacBook，不對外公開；
POS 的寄售序號品已有品牌、售價、狀態，但沒有顏色、露數、缺件、瑕疵、配件、照片、影片、保留。

## 決定

1. **POS 主動推、雲端不連進店內**，與 ADR-027 同一原則。
2. **沿用線上點餐的雲端**（order.lukeng-camp.com）：新增 `PUT /integration/tents`（HMAC）與公開
   `GET /api/tents`（只允許官網網域的 CORS）。照片走新的 `/integration/tent-photos`，存同一個 R2 桶的 `tent-photos/` 前綴（見第 7 點）。
3. POS 在 `onlineorder` 模組新增 `online_tent_listings`、`online_tent_listing_photos`、
   `online_tent_publications`，只存 POS 原本沒有的欄位；售價、品牌、狀態讀序號品本身。照片沿用 `menu_photos`。
4. **以內容雜湊驅動推送**：背景工作每 60 秒組清單、比對雜湊，有變才推；存檔後另外立即試推一次。
   不在銷售、退貨、寄售流程裡加推送掛勾。
5. 「保留中」只是官網顯示用的標記，不是庫存保留，不擋結帳。
6. 推送內容採白名單，寄售人、成本、抽成、備註一律不出店。
7. **售出後官網與雲端的照片都刪、POS 留著**：帳篷照片放 R2 獨立前綴 `tent-photos/`，雲端每次收清單就刪掉
   沒被引用的照片；POS 不記推送紀錄，雲端回 `missing_photo` 才補推，退貨回庫自動復原。

## 替代方案

- **官網 Worker 自己收推送、自建 R2**：要再做一套簽章、防重放、照片上傳和部署設定，跟線上點餐重複。不採用。
- **POS 每次在銷售／退貨／寄售流程裡呼叫推送**：要改好幾個模組，漏一個就不同步；斷網時還要補推機制。
  雜湊比對自動涵蓋所有會改到清單的事件。不採用。
- **把官網要的欄位直接加在 `serialized_items`**：讓核心庫存表背著只給官網用的欄位，非帳篷商品也都多了空欄。不採用。
- **POS 匯出檔案、手動上傳**：店主要自動。不採用。

## 影響

- POS：三張新表＋migration、背景工作多一項、寄售頁多一個分頁。
- 雲端：D1 migration 一支、兩個端點；官網頁與線上點餐共用一個雲端，雲端掛掉時官網清單也讀不到
  （官網會顯示「暫時載入不了」與 LINE 詢問）。
- 官網：資料網址改讀雲端，部署須在雲端與 POS 上線之後。
