# ADR-021：寄售人依「未稅」售價分潤

- **Status**: Accepted（2026-09-11）

- **Context**:

  寄售品賣出時，發票由店家對全額開立，營業稅由店家申報繳納。原 §7.2 以**含稅**售價算抽成：

  ```
  抽成金額   = round_ntd(售價 × commission_pct / 100)
  應付寄售人 = 售價 − 抽成金額
  ```

  於是寄售人拿到含稅價的份額，稅卻全由店家繳，等於店家替寄售人吸收了他那份稅：

  ```
  含稅 1050、抽成 50%、稅 5%
    舊式：寄售人 525、店家 525 → 繳稅 50 後店家實得 475
  ```

  約定的「對半分」實際變成 47.5 : 52.5。2026-09-11 店主裁示：寄售人要拿**未稅**價的份額，
  上例寄售人只拿 500。

- **Decision**:

  1. 先把含稅售價還原為未稅（與發票同式 `split_tax_inclusive`），再依抽成比例分：

     ```
     未稅         = round_ntd(售價 ÷ (1 + tax_rate))
     店家未稅抽成 = round_ntd(未稅 × commission_pct / 100)
     應付寄售人   = 未稅 − 店家未稅抽成
     ```

     實作為 `core/money.consignment_split(gross, pct, tax_rate)`；捨入慣例沿用舊式——
     四捨五入的是店家抽成，寄售人拿剩下的。

  2. **資料結構不變**。`consignment_settlements.commission_amount` 記「店家留下的含稅部分」
     ＝ `售價 − 應付寄售人` ＝ 未稅抽成 ＋ 營業稅。如此 DB 約束
     `commission_amount + payout_amount = gross` 照舊成立，現金對帳（§7.4）、寄售付款、
     退貨反轉（§7.7）、報表的「店家收入只認抽成」（§7.3）都不必改。上例存為
     `commission_amount = 550`、`payout_amount = 500`。

  3. `tax_rate` 取自 `settings`（結帳當下的有效設定），不得寫死；`tax_rate = 0` 時退化為舊式。

  4. **只影響之後的銷售**。既有結算列不回溯改寫（開店前只有測試資料）。

  5. 整單折扣照舊不分攤到寄售人；活動折扣照舊按比例（`gross` 為折後價，再套本式）。

- **Consequences**:

  - 寄售人拿的比舊式少約 `稅率 ÷ (1 + 稅率) × 寄售人比例`（稅 5%、對半分時約少 2.4%）。
  - 寄售頁「抽成」欄與報表的寄售抽成收入顯示的是**含稅**的店家份額（上例 550，其中 50 是稅）。
    報表的含稅／未稅並列另案處理；屆時寄售的未稅抽成 = `commission_amount − 該品項分到的稅`。
  - 寄售合約文字只寫「寄售抽成比例」，未載明計算基礎，本 ADR 不改合約文字。
