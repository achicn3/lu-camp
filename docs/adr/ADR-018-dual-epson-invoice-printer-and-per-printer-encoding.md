# ADR-018：發票專屬印表機與「逐機」中文編碼

- **Status**: Accepted（2026-08-27）

- **Context**:

  店家在 2026-08-27 加購第二台 EPSON TM-T82III，要求把「發票」與「其他所有紙」分開：
  `192.168.0.42` 只印電子發票證明聯，`192.168.0.44` 印收據／商品明細聯／收購憑證聯
  （含顧客簽名）／出餐單。

  接上後第一張測試頁在 `.44` 印出**整捲亂碼**。以 ESC/POS `GS I` 直接向兩台問身分：

  | | `192.168.0.42` | `192.168.0.44` |
  |---|---|---|
  | 型號（`GS I 67`） | TM-T82III | TM-T82III |
  | 韌體（`GS I 65`） | `15.05 ESC/POS` | `20.09 ESC/POS` |
  | 序號（`GS I 68`） | `X7BJ020997` | `X7B4090696` |
  | **字型（`GS I 69`）** | **`TAIWAN BIG-5`** | **`CHINA GB18030`** |

  同型號、不同字型 ROM。系統從 T15 起把中文寫死成 Big5
  （`escpos_receipt._line` 的 `text.encode("big5")`），Big5 位元組進到 GB18030 的字型表
  就是亂碼。這是韌體/字型 ROM 層級的差異，**面板設定改不掉**。

  實機分別以 big5／gb18030／gbk 各印一次同一句繁體字：**gb18030 與 gbk 都正確印出繁體**
  （GBK 的編碼空間涵蓋繁體字，字型 ROM 也有對應字形）。紙寬確認 `.44` 一行同樣是
  34 半形（57mm 紙），現有版面常數不必調整。

  另有兩件現場事實：錢櫃的線**插在 `.42`（發票機）那台**的 drawer port；而程式把錢櫃
  硬綁在「收據機」那條連線上。

- **Decision**:

  1. **中文編碼隨機器走，不是全域常數。** `PrinterEndpoint` 增 `encoding` 欄位，
     由各台自己的 `AGENT_*_ENCODING` 提供（預設 `big5` ＝ 既有單機部署行為）。
     `escpos_receipt` 的 `_line` 改為 `line_encoder(encoding)` 產生的注入函式，
     排版程式不再認識任何特定編碼。

  2. **`.44` 用 `gbk`，不用 `gb18030`。** 兩者對常用繁體字結果相同，但 gb18030 對罕用字
     會送出 4 位元組序列，字型 ROM 是否有對應字形沒有保證；gbk 是純 2 位元組，編不出
     的字照既有規矩退成 `?`。**印錯字不如印問號**——店員看得出來。

  3. **新增「發票專屬機」角色**（`AGENT_INVOICE_HOST`，選配）。`/print/einvoice` 與
     `/print/raw`（Amego 補印的原樣版面）送發票機；`/print/receipt`、`/print/detail`、
     `/print/acquisition`、`/print/kitchen` 一律留在收據機。解析點只有一個
     （`AgentDevices.einvoice_printer`），比照既有的出餐機（`kitchen_ticket_printer`）。
     未設 → 退回收據機，單機店家升級後行為不變。

  4. **缺紙不改印另一台。** 與出餐機同一原則：證明聯有兌獎聯性質，改印到收據機會讓
     店員以為印好了，而客人手上什麼都沒有。失敗就是失敗，如實回 409/503。

  5. **錢櫃的目的地獨立設定**（`AGENT_DRAWER_HOST`，未設即收據機）。錢櫃只送 kick
     指令、不出紙，故指到「發票專屬機」不違反該機的專屬定位。`/devices/status` 的錢櫃
     狀態改依附**它實際插的那台**——收據機在線不代表錢櫃踢得動。

  6. **`/devices/status` 列管發票機**（`invoice-1`）。它可能擺在櫃檯另一側，離線時
     店員未必看得到；同一台在單次輪詢中只探測一次（錢櫃與發票機共用連線時不重複開 TCP）。

  7. **編碼名打錯即報錯**（`MissingDeviceConfigError` → 503），不默默退回 Big5。
     退回預設的下場是實機印出一整捲亂碼才被發現。

- **Consequences**:

  - `escpos_receipt` 的 57 處 `_line(...)` 改為注入的 `emit(...)`，五個排版 block 多一個
    參數。版面位元組在預設（big5）下**逐位元組不變**，既有版面測試全部原樣通過。
  - 前端零改動：列印按鈕位置、`frontend/lib/agent.ts` 的端點都沒變，去哪一台由代理決定。
    `/devices/status` 目前沒有任何畫面在用。
  - 出餐機（`AGENT_KITCHEN_HOST`）也取得自己的 `AGENT_KITCHEN_ENCODING`；本店尚未接第三台。
  - **買新機時要多問一件事**：TM-T82III 有 Big5 與 GB18030 兩種字型 ROM，型號欄看不出來，
    要對機器送 `GS I 69`（`1D 49 45`）才知道。設定寫錯不會報錯，只會印出亂碼。

- **Alternatives considered**:

  - **把 `.44` 的中文改走點陣圖**（用 repo 內建 Noto Sans TC 畫成圖再送，標籤機就是這樣做的）：
    可行且與字型 ROM 完全脫鉤，但整張收據轉點陣會明顯變慢、字也較糊，而 gbk 這條路
    實測就能正確印出繁體。真的遇到 ROM 沒有的字形時再考慮。
  - **對調角色（`.42` 當收據機、`.44` 當發票機）**：解決不了問題——證明聯上「電子發票證明聯」
    等字樣同為中文，Amego 回傳的原樣版面亦為 Big5，換過去一樣亂碼；且 `.42` 的收據版面
    是實機量過的，換機還得重驗。
  - **全域改用 gbk**：`.42` 是 Big5 機，改了換它亂碼。這正是「編碼必須隨機器走」的證明。
  - **錢櫃沿用收據機那條連線**：線實際插在 `.42`，沿用等於踢不動；且狀態頁會謊報在線。
