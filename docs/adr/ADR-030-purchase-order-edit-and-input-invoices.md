# ADR-030：採購單事後可改（含已收貨）、進項發票獨立成表

- 狀態：已採納（店主裁示 2026-10-08）
- 相關：docs/70、Phase 5 採購（docs/05 purchasing）、ADR-023

## 背景

採購單送出後完全不能改，收貨後打錯數量、進價或選錯商品只能另開單、手動調庫存。
廠商又常在收貨後隔月才開發票、甚至整月合併一張，而原設計把發票欄位放在單一收貨批次上，
只能登一次、不能改，也無法表達「一張發票涵蓋多批收貨」。

## 決定

1. **整張覆寫的修改端點**（`PUT /purchase-orders/{id}`）：草稿全員可改；已下單／部分到貨／已收貨僅管理者，寫稽核。
   部分到貨／已收貨可改「已收」數量。
2. **庫存隨改隨調**：以商品為單位比對改前改後已收總數，差額寫新異動原因 `PURCHASE_CORRECTION`；
   扣不夠（已賣出）整筆擋下。不另設「待調整」狀態——店主要的是改完就對。
3. **成本只認最近一次進貨**：改前或改後最近一次進貨是這張單才同步商品成本；已成交的成本快照不追溯。
4. **進項發票獨立成表** `purchase_input_invoices`，收貨批次以 `input_invoice_id` 指向它：
   一批最多一張、一張可多批（跨採購單、同一供應商）。原收貨上的發票欄位搬移後移除。
   發票可事後登錄；修改、刪除限管理者並寫稽核。

## 取捨

- 換商品不做專用動作：移除錯的列＋加對的列，庫存差額結果相同，介面少一種概念。
- 不支援一批收貨拆兩張發票：極少見，資料模型會從 FK 變成多對多＋金額分攤，不值得。
- 發票金額與收貨金額不一致只提醒不擋：運費、折扣、尾差都是正常情況，以發票上印的為準。
- 修改已收貨的單會改到歷史（數量、成本），所以限管理者並保留完整前後值稽核，而不是做沖銷單。
