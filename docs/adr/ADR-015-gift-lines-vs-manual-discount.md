# ADR-015：贈品為獨立明細性質，臨時折扣落到明細實付

- **Status**: Accepted（2026-08-03）

- **Context**:
  門市要能在結帳當下送東西（贈品）與臨時改價（折扣）。系統原本唯一的減價機制是全店活動
  百分比折扣（campaign），沒有手動改價、贈品、負數明細或折扣原因的概念。

  兩個約束決定了設計空間：

  1. `sale_lines.unit_price` / `line_total` 是折後實際成交價，**退貨退款、客人簽署同意書、
     電子發票品項、五份報表的毛利全都直接讀它**。任何新的減價方式若沒有正確落到這條線上，
     就會同時弄錯退款金額、讓發票送不出去、並污染毛利報表。
  2. `amego.py` 硬性要求 **Σ 品項小計 == 發票總額**，不符即拒送，且該發票**永遠**送不出去。

  另有兩條既有邊界：`core/money.py` 的 `discounted_price()` 明確拒絕 100% 折扣；
  `menu_items.unit_price` 有 `gt=0` 且有測試以「贈品」為名釘住——「建 0 元品項當贈品」
  的偏方已被明確關閉。

- **Decision**:

  1. **贈品是獨立的明細性質，不是 100% 折扣。** 新增 `sale_lines.line_kind`
     （`NORMAL｜GIFT`），與品項種類 `line_type` 正交（故「贈送一件序號品」表達得出來）。
     贈品照樣扣庫存、寫 `GIFT` 庫存異動、成交 0 元，但保留 `original_unit_price` 與
     `cost_snapshot`。其原價價值**絕不寫入 `discount_amount`**。
  2. **臨時折扣必須落到明細。** 新增 `manual_discount_amount` 與 `net_amount`
     （＝`line_total − manual_discount_amount`），並維持 `line_total` 的原語意不變。
     **`Σ net_amount == sale.total == Σ tenders`** 為核心等式，以 DB CHECK 與 deferred
     trigger 守護。所有「該用實付」的地方（退款、發票品項、毛利）明確改讀 `net_amount`。
  3. **一般行的實付不得為 0。** 折到 0 元＝變相贈品；要免費一律開贈品，否則贈品的數量與
     成本在報表上統計不到。定價純函式與 DB CHECK 兩層都擋。
  4. **贈品成本自成一桶，不進 `gross_margin`。** 另計 `contribution_margin`
     ＝淨毛利 − 贈品成本。
  5. **不建立主管核准機制、不設任何上限**（店主裁示）。事後稽核靠折扣報表的「依店員」段
     與 `sale_adjustments` 的完整留痕。

- **Alternatives**:
  - *把 GIFT 加進 `line_type`*：會混淆「品項種類」與「商業性質」兩個正交概念，
    且「贈送序號品」變得無法表達。
  - *贈品做成 100% 折扣*：`discounted_price()` 明確拒絕 100%；且贈品價值會混進
    `discount_amount`，污染活動報表，贈品的件數與成本再也統計不到。
  - *折扣只掛在訂單層、不落明細*：`Σ 品項 ≠ 發票總額` → **每一張發票都送不出去**；
    退貨與毛利也失去逐行歸屬。
  - *改寫 `unit_price` 為折後價*：牌價與折扣的留痕一起消失，客訴與稽核時無從還原。
  - *發票品項保留 0 元贈品行*：本 repo 對「平台是否接受 0 元品項行」**無任何佐證**，
    不賭；排除贈品行後 Σ 仍等於總額。

- **Consequences**:
  - ＋ 折扣與贈品在資料模型、退貨、發票、報表四層都分得開，事後可完整還原。
  - ＋ 成本快照凍結了「報表今天的行為」，日後調整商品成本不再回頭改寫歷史毛利
    （順帶修掉一個既有缺陷）。
  - － 讀 `line_total` 的既有程式碼必須逐處判斷該不該改讀 `net_amount`；這是一次性的
    人工審視，沒有捷徑。
  - － 客顯購物車快照多了三個欄位，**四個產生點**必須同步升版，少改一處即所有購物金
    結帳失敗（已以 `content_version` 與整合測試釘住）。
  - － 無核准機制：任何能結帳的人都能打任意折扣、送任意贈品。這是明確的商業取捨。

- **Trade-off**:
  以「多一個 `net_amount` 欄位＋一次全面的讀取點審視」換取「折扣與贈品永遠拆得開」。
  相對地，`line_total` 保持原語意不變，讓既有讀取點不會**突然改變意義**——要改的地方
  必須是被明確改過的地方，而不是靜默地變了。
