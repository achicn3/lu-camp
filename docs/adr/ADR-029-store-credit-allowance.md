# ADR-029：混合付款的購物金部分以折讓處理

- 狀態：已採納（店主裁示 2026-10-07）
- 相關：ADR-014（退貨的發票處置）、ADR-026（全額購物金不開票）、docs/16、docs/24

## 背景

ADR-026 起全額購物金付款不開發票；混合付款（購物金＋現金／LINE Pay／台灣Pay）照整筆成交總額
開一張發票，購物金那部分也算進發票金額。兩者口徑不一致：同樣是購物金付的錢，混合時課稅、
全額時不課稅。

## 決定

1. **混合付款**：結帳照整筆總額開發票（客人拿到的證明聯不變）；**平台確認開立後**，系統自動
   對「購物金付款金額」開一張折讓（G0401，`source=STORE_CREDIT`），應稅銷售額＝非購物金部分。
   - 一張發票至多一張購物金折讓（資料庫部分唯一索引），重送、重複回執都不會開第二張。
   - **不需買受人簽名同意**（店主裁示；稅務風險已告知店主，建議開店前請記帳士確認）。
   - 交易的發票狀態維持「已開立」——這張折讓是購物金的稅務處理，不是退貨。
   - 手開紙本發票不代管（同既有規則）；歷史交易不追溯。
2. **全額購物金**：維持 ADR-026，不開發票。
3. **整筆作廢**（店長在交易紀錄作廢）：**先作廢購物金折讓（G0501），平台受理後再作廢發票
   （F0501）**。
   - 折讓還沒送出（未認領）→ 直接取消那筆折讓，照常作廢發票。
   - 折讓送出中、結果未回 → 記下「要作廢」，等 G0401 結果：成功就續送 G0501；失敗（平台從未
     成立）就視為已作廢、續送 F0501。
   - G0501 送出前一律先以 allowance_query 對帳（同 F0501／G0401 的「對帳先行」），回應遺失不會
     重送或漏送。
   - **F0501 要等平台把折讓作廢處理完**（測試環境實測：G0501 受理後約 6 分鐘才生效，之前送
     F0501 會被拒「已存在折讓單」）。未完成就維持待送出、寫明原因，背景 5 分鐘後自動再試。
4. **退貨**：發票已有購物金折讓時，退貨折讓金額＝**本次退款中非購物金的部分**（購物金那部分
   在結帳時已折讓過）。例：$1,000（購物金 $300＋現金 $700）全退 → 退回購物金 $300、現金 $700，
   折讓 $700；累計折讓剛好等於發票總額。沒有購物金折讓的舊交易照舊（折讓＝退款總額）。
   - **同月整筆退照舊作廢發票**（ADR-014）：購物金折讓不算「這張發票已折讓過」，作廢時照第 3 點
     先作廢它、再作廢發票。跨月整筆退則折讓非購物金部分（上例 $700）。
   - 既有不變量照舊：發票已有任何（未作廢的）**退貨**折讓 → 退貨一律繼續折讓、不作廢發票。

## 影響

- 資料：`invoice_allowances` 加 `source`（RETURN／STORE_CREDIT）、`void_requested_at`；
  佇列動作加 `ALLOWANCE_VOID`（G0501）。migration 一支。
- 背景自動送出加入 G0501；佇列頁顯示「作廢折讓」。
- 申報（發票登記簿）：購物金折讓是真的折讓，列入折讓；已作廢的折讓不計。
