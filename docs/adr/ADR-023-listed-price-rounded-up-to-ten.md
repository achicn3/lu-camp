# ADR-023：上架售價一律 10 的倍數（無條件進位），只約束系統自動帶出的價格

- **Status**: Accepted（2026-09-19）

- **Context**:

  店主要求「上架售價都要為 10 的倍數，也就是 0 結尾，無條件進位（21 → 30）」。

  現況是 §7.9 的建議售價算完就直接填進「上架售價」欄位，結果架上價格散落成
  1145、2111、1954 這種數字。零頭在實體店面有兩個實際成本：標價牌難讀、找零要備一元硬幣。

  同一時間店主另裁示：**不擋店員手動輸入**。特價 99、與寄售人談定的 2350，都要填得進去。

  於是要決定兩件事：進位放在計算的哪一層，以及「系統自動帶出」包含哪些路徑。

- **Decision**:

  1. **進位與毛利式分成兩支函式，不合併。**
     `suggested_price()` 維持 §7.9 的毛利式與「全程只四捨五入一次」；
     `suggested_listed_price()` = `round_up_to_listed_step(suggested_price(...))`，
     是唯一該填進畫面或商品的建議價。前端 `pricing.ts` 鏡射同一組（`roundUpToListedStep`）。

     合併成一支會讓釘住單次捨入的既有回歸測試失去鑑別力：1145 與 1146 進位後同為 1150，
     「先取整未稅再加稅」的錯誤實作就再也測不出來。那條測試是 ADR-016 留下的防線，不能拆。

  2. **級距是 10，定義在 `LISTED_PRICE_STEP`**，前後端各一份常數、值相同。
     無條件進位；已經是倍數就不動；0 保持 0（成本 0 的贈品不該被抬成 10 元）。
     負數與 `null` 原樣傳回——那是上游算不出來的訊號，悄悄變成 0 或 10 會讓店員
     以為系統給了建議價。

  3. **「系統自動帶出」＝所有由系統填進售價欄位的數字**，目前四處：
     - 收購頁「套用建議（目標毛利 N%）」
     - 收購頁「估計轉售價 → 上架售價」的**自動同步**（含「帶入客人實付價」按鈕）
     - 採購頁建立一般商品時的建議售價
     - 餐飲菜單建立品項時的建議售價

     只做第一項的話，店員最常走的其實是第二項，架上仍然會出現 2111；漏掉採購與菜單，
     那兩條路進來的商品一樣會有零頭，而它們同樣要貼標籤、上菜單板。前兩者必須走同一個
     進位函式，否則自動同步的「認領」比對（`autoFilled`）會永遠不相等而反覆覆寫店員的輸入。

     **前端函式命名與後端對齊**：`exactSuggestedPrice()` 對應 `suggested_price`（不進位），
     `suggestedListedPrice()` 對應 `suggested_listed_price`（已進位）。第一版前端把不進位的
     那支叫 `suggestedListedPrice`，採購頁就是因為這個同名不同義而漏掉進位（2026-09-19 審查）。

  4. **手動輸入完全不擋**，也不做「你填的不是 10 的倍數」這類提示。
     裁示如此；而且寄售的架上價是與寄售人談定的，系統無權更動。

- **Consequences**:

  1. **實際毛利會略高於目標**，最多高出 9 元所對應的百分比。進位只進不退是刻意的：
     這個數字的用途是「至少達到目標毛利」，退位會讓店家少賺。

  2. 既有商品的售價**不追溯改動**（裁示）。架上會有一段時間新舊並存，
     舊標籤不必重印，報表與已成交紀錄完全不受影響。

  3. 前後端各有一份實作，靠 `__tests__/acquisition-pricing.test.ts` 的對齊測試
     （建議價 1145 → 1150）釘住。動其中一邊就要動另一邊。

  4. 進位是**價格呈現規則**，不是第二次捨入。它發生在毛利式算完之後，
     所以 §7.9 的「全程只四捨五入一次」依然成立。

- **Alternatives considered**:

  - *四捨五入到 10*：1144 會變 1140，實際毛利低於目標。店主要的是「進位」，
    而且少賺沒有任何補償機制。
  - *手動輸入也強制進位*：店主否決（特價 99、寄售談定價都要填得進去）。
    強制的話寄售架上價會被系統單方面改掉，店家與寄售人的分潤基準就對不上。
  - *把進位塞進 `suggested_price()`*：見決策 1，會廢掉 ADR-016 的防線。
  - *級距做成 settings*：目前只有一間店、一個值，可設定是想像出來的需求
    （見 memory「calibrate: real scenarios, single-PC」）。真要多級距時再抽。
