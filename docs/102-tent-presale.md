# 102 — 寄售帳篷預售（帳篷還在原主家就先上官網）

> 狀態：**草案，待店主審**（2026-10-31）。延伸 docs/97（寄售帳篷上官網）；決策見 ADR-035。

## 1. 要解決什麼

賣家用 Google 表單登記想寄售的帳篷。帳篷**還在賣家家裡**時，就先放上官網賣；
買家想看要先預約，店員再聯絡賣家把帳篷帶來。帳篷送到店、照平常流程辦寄售（平板簽切結、填身分證）後，
官網那頂直接變成現貨。

## 2. 店主裁示（2026-10-31）

| # | 裁示 |
|---|---|
| 1 | 賣家表單用 **Google 表單**，店員看過再抄進 POS（POS 不做表單、不接 Google）。 |
| 2 | 買家**不用填預約日期、不用勾保留中**；官網只要說清楚「這頂想看要先預約」。 |
| 3 | 官網上預售跟寄售中的**混在一起**，加「預售」標籤。 |
| 4 | 帳篷送到店後，**建寄售單時選這筆預售帶入**，官網那頂直接變現貨。 |
| 5 | 預售階段**不收身分證**；身分證照現行規定在到店辦寄售時收（收購/寄售對象必須有 national_id 不變）。 |

## 3. 店員操作

### 3.1 建預售（「更多 → 官網寄售帳篷」）

頁面上方新增「＋新增預售」。填：

- **必填**：品牌、帳篷名稱、售價（客人實付含稅價）、賣家姓名、賣家電話。
- **選填**（同現貨帳篷）：顏色、露數、缺件、瑕疵、額外配件、YouTube 影片、照片（最多 8 張，從表單下載後上傳）、備註（只給店員看）。
- 「上架官網」勾選同現貨；預設不勾，店員確認資料齊了再勾。

清單上預售跟現貨列在一起，編號欄顯示預售編號（`P1-XXXXXXXXXX`），狀態欄標「預售」。
預售列多兩個動作：**編輯**、**取消預售**（賣家不賣了／帳篷沒送來 → 官網拿掉，POS 留紀錄）。

賣家姓名、電話**只在 POS 看得到**，不進官網清單、不寫 log。

### 3.2 帳篷送到店 → 轉成寄售

照現在的收購頁（非排隊收購）建**寄售**單：查找/建檔賣家（填身分證）→ 寄售分頁 →
鑑價列多一個「從預售帶入」下拉，只列**還沒轉成寄售的預售**。選了之後：

- 品名、品牌、上架售價自動帶入（店員可改，以收購頁送出的為準）。
- 送出成功（同一個交易內）：預售那筆接上新建的序號品，照片、顏色、露數、缺件、瑕疵、配件、影片、上架勾選全部沿用。
- 官網那頂變成現貨（「預售」標籤消失），舊的預售編號網址自動轉到新編號。

一筆預售只能帶入一次；帶入的寄售單之後被作廢，預售**不會**回到未轉狀態（序號品作廢後官網自然消失，要重來就重建預售）。

## 4. 官網

- 清單卡片、詳情頁加「**預售**」標籤；詳情頁說明：「這頂帳篷目前在原主家，想看請先 LINE 預約，我們會請原主帶來店裡。」
- 主按鈕改為「**LINE 預約看這頂**」；不顯示「來店看實品」與營業中提示。
- 篩選列多一個「現貨／預售」切換（預設全部）。
- 首頁按鈕的「目前 N 頂」含預售。
- 預售取消：直接從清單消失（不進「最近售出」）。

## 5. 資料模型

沿用 `online_tent_listings`，讓一列可以是「預售」或「現貨」：

- `serialized_item_id` 改**可為 NULL**（NULL＝還沒到店的預售）。
- 新增欄位：`presale_code`（唯一，`P{store_id}-` + 10 碼）、`presale_brand_id`、`presale_name`、`presale_price`（Numeric，整數元）、
  `presale_seller_name`、`presale_seller_phone`、`presale_note`、`presale_cancelled_at`、`converted_at`。
- CHECK：`serialized_item_id IS NOT NULL OR (presale_code、presale_name、presale_price 都不是 NULL)`。
- 現貨列的品牌／名稱／售價仍一律讀序號品；預售列讀 presale_* 欄位。轉成寄售後 presale_* 保留作紀錄。

官網清單（feed）每頂多兩個欄位：`presale: bool`、`formerIds: string[]`（轉成寄售後放原本的預售編號）。
預售列的 `id` 用預售編號、`status` 為 `available`（或 `reserved`，若店員仍勾保留中）。雲端（D1／R2）**不需改**：清單是整份 JSON，照片照舊。

## 6. 對 POS 的影響（絕對不能影響 POS）

- 收購 API：寄售鑑價列多一個**選填**的 `presale_listing_id`；不帶時行為完全不變。
- 帶入失敗（已被帶過、已取消、不同店）→ **整張寄售單不建立**並回明確錯誤，避免寄售成功但官網沒接上。
- 結帳、退貨、寄售結算不改。

## 7. 測試

- 單元/整合：建預售、必填驗證、取消、feed（預售/現貨/轉換後 formerIds/取消後消失/不含賣家資料）、
  收購帶入（成功沿用照片與欄位、重複帶入擋、取消的擋、不帶時與原本相同）、migration 升降。
- 前端：預售表單、清單標示、收購頁帶入下拉。
- 瀏覽器煙霧：建預售（含照片）→ 官網看得到預售標籤與 LINE 預約 → 收購頁帶入建寄售 → 官網變現貨、舊網址轉新編號。

## 8. 待店主確認

1. 買家**也可以**在預售時被勾「保留中」嗎？（建議：可以，沿用現有勾選；不勾也沒關係。）
2. 預售的售價是否要等到店檢查後才能定？（建議：預售時先定，到店後店員在收購頁可以改。）
