## 2. 退款金額（最重要的一節）

沿用既有退貨引擎（`returns`），**不另寫一套**：兩個頁面退出去的錢一定對得起來。

- **每行退款＝差額法**（`returns/refund.py`）：`round_ntd(實付 × 累計退量 ÷ 數量)` 的差，最後一份吸收尾差，
  累計恆等於原實付。實付（`net_amount`）已含整單折扣分攤。
- **退款去向（tender 分配）**：餐點**不能用購物金付**（M1 不變量），所以：
  - 二手部分：購物金優先（既有規則），其餘退外部付款。
  - 餐點部分：**只退外部付款**（現金／LINE Pay／台灣Pay），永不退成購物金。
  - 以累計差額計算：`購物金已退 = min(購物金付款, 二手累計退款)`、
    `外部已退 = 餐點累計退款 + (二手累計退款 − 購物金已退)`，本次＝前後差。
- **會員點數**：點數當初只發非餐飲部分 → 沖回只按**二手**的退款比例（既有 D-8 口徑），餐點退款不沖點。
- **發票**：同一套政策（`returns/invoice_policy.py`）——全部付費品項退光且本月開立 → 作廢；其餘 → 折讓。
  混合單只退餐點＝部分退 → 折讓。
- **現金退款**需開帳（不變量 8）；LINE Pay 走既有 durable 退款日誌（防重退）；台灣Pay 店員另退後勾確認。

## 3. 份數

退款時勾「這份還能賣」→ 用該明細的 `menu_stock_consumed`（扣到的版本）加回，規則同作廢：
同一營業日、版本未變才加回（店員按過「改成」＝已重數，不加回）。不勾＝不動份數。

## 4. 畫面

`/fnb-sales`「餐飲交易紀錄」（店員可看可退）：
- 清單：預設今天，可選日期；每列：時間、內用桌號／外帶、餐點小計、整單總額、已退金額、付款方式、發票狀態。
  只列**含餐點**的交易。
- 明細：所有品項（餐點可勾選與選份數；二手灰底、附「到交易紀錄退貨」連結）、整單總額、餐點小計、
  已退份數／金額。
- 退款對話框：退貨預覽（後端算的退款金額、發票處置）→ 原因 → 「還能賣」→ 需要時請客人在顧客螢幕點同意 → 送出。
