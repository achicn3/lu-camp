## 1. 這次多了什麼（docs/63 §13；M1d）

| 變更 | 影響到 | 要做的事 |
|---|---|---|
| 線上點餐可上架現有零售商品（帶回家）；線上單付款後要按「已交貨」才結單 | 資料庫＋後端 | migration `c3e7a9d1f5b8` |
| 「菜單」→「線上發布」分頁多「帶回家（零售商品）」列表與新增／編輯頁 | 前端 | 重新 build 前端 |
| POS「線上訂單」清單多「已付款・待交貨」與「已交貨」按鈕 | 前端 | 重新 build 前端 |
| 庫存明細多兩種異動「線上訂單保留／保留加回」 | 後端 | 不用另外處理 |

> 沒有新套件。正式機**仍先不設定**線上點餐雲端，所以客人端與 POS「線上訂單」按鈕都看不到——這是預期的。
> 日後設定雲端時：**先套用雲端 D1 migration（含 `0006_retail_and_fulfillment`）、部署新版 Worker，再從 POS 發佈**。

## 2. 升級步驟

照 docs/43 §3 的指令依序做。`alembic current` 應顯示 **`c3e7a9d1f5b8 (head)`**。

## 3. 驗證（每一項都回報結果）

1. docs/43 §4 開頭的 `curl`／`launchctl` 檢查：三個 `state` 都是 `running`、兩個 http 都是 `200`。
2. 請**店主**打開「菜單」→「線上發布」：有「帶回家（零售商品）」區塊與「新增帶回家商品」按鈕；按下去在「搜尋商品」打
   一個現有商品的名字，下面會列出商品（不用真的儲存）。
3. 請**店主**在 POS 結一筆一般商品：照常可結、庫存照常扣。

## 4. 出問題怎麼退

- 只退程式：`git checkout <記下的 commit>`，再照 docs/43 §6 重 build 前端、`install-launchd.sh`。
  前提是**還沒有任何線上單保留過帶回家商品**（正式機沒設定雲端時一定沒有）：舊程式認不得「線上訂單保留」這種庫存異動，
  一旦有了，舊程式打開那個商品的庫存明細會出錯——這時**不要退**，把狀況回報店主，由開發端修正。
- 降版 `c3e7a9d1f5b8` 在**已有帶回家商品設定、線上保留異動或要交貨的線上單**時會拒絕——只退程式、不要降資料庫。
