## 3. 口徑（**最重要的一節**）

報表最容易出錯的不是計算，是分母。以下全部要寫進畫面說明文字，不能只寫在這份文件裡。

### 3.1 什麼算一「組」

**一筆含餐飲品項的銷售 ＝ 一組。**

- 只有**含至少一行 `MENU`** 的銷售才計入；純二手/一般商品的單不算
- `status = VOIDED` 的單一律排除
- `service_mode` 為 `NULL` 的單不會有餐飲行（docs/35 的 CHECK 保證兩者自洽），故不會落入分母

### 3.2 佔比的分母是「有餐飲的單」，不是全店訂單

> **這一條若寫錯，數字會誤導經營判斷。**
> 分母若用全店訂單數，某天賣了很多二手裝備就會把內用佔比稀釋掉，
> 看起來像「內用生意變差」，實際上餐飲完全沒變。

`內用佔比 = 內用組數 ÷ (內用組數 + 外帶組數)`。畫面上標明分母。

### 3.3 客單價只算餐飲行

一筆單可能同時有餐飲與二手商品（例如邊吃邊挑裝備）。若把整單金額當客單價，
內用客單價會被同行的二手成交灌水。

- **主要指標**：`餐飲客單價 = 該組 MENU 行的 net_amount 合計 ÷ 組數`
- **另列對照**：整單合計（含非餐飲），供想看「這組總共花多少」時參考

### 3.4 內用與外帶的客單價**不可直接比較**

docs/35 §1.1 的既有規則：**外帶餐飲不累點、不折扣、不可用購物金折抵**。
兩者的計價條件本就不同，畫面須標注這一點，不要讓人得出「外帶客人比較大方」的錯誤結論。

### 3.5 退貨

docs/35 已定：**餐飲品項不支援退貨**。故本報表不需處理餐飲退貨；
但整單作廢（`VOIDED`）仍要排除（§3.1）。

## 4. API

新增於既有 `reports` 模組（限 MANAGER，與其他報表一致）。

```
GET /api/v1/reports/dine-in
    ?date_from=&date_to=&granularity=day|week|month|quarter
```

回應：

| 區塊 | 內容 |
|---|---|
| `summary` | 內用/外帶各自的**組數**、**佔比**、**餐飲營收**、**餐飲客單價**、**整單合計** |
| `trend` | 依 `granularity` 分桶的時間序列，每桶含內用/外帶組數與餐飲營收（空桶補 0） |
| `hourly` | 0–23 時各自的內用/外帶組數（**台北時間**） |

- 分桶沿用 `store_bucket_bounds`，與既有 R6 趨勢同一套，桶與 `[from, to)` 取交集
- 時段以**台北時間**的小時切；用 UTC 會讓尖峰整體位移 8 小時

## 5. 畫面

報表頁新增分頁「**餐飲內用/外帶**」（現有 14 個分頁之後）。

1. **摘要卡**：內用 N 組（佔比 X%）／外帶 M 組（佔比 Y%），各自營收與客單價
2. **趨勢折線**：日/週切換，兩條線（內用、外帶）
3. **時段長條**：0–23 時，兩色堆疊或並列
4. **口徑說明**：§3.2、§3.4 兩句話必須顯示在畫面上，不是藏在說明文件裡

CSV／Excel 匯出沿用既有報表的匯出機制。

---

## 6. 不做的事（本版）

- **不做桌號維度**（哪一桌翻桌率高）——桌號是給出餐核對用的，不是座位管理
- **不做翻桌率／滯留時間**——系統沒有「入座時間」，只有結帳時間，算不出來
- **不與叫號系統（docs/38）合併統計**——那是收購的候位，與餐飲無關

---

## 7. 測試

- **口徑**：純二手單不計入；`VOIDED` 排除；同時含餐飲與二手的單，
  **組數算一組、餐飲客單價只算 MENU 行**
- **佔比**：分母是「有餐飲的單」——加入大量純二手單後，佔比**不得改變**
  （這條直接守 §3.2）
- **時區**：台北 00:30 與 23:30 的單分別落在正確的營業日與時段桶；
  用 UTC 會讓尖峰位移 8 小時
- **分桶**：空桶補 0；桶與查詢區間取交集；各桶組數加總 ＝ 全期組數
- **權限**：限 MANAGER（CLERK 取得 403）
- **瀏覽器 E2E**（CLAUDE.md §1 強制，有 UI）：分頁載入、切換日/週、
  數字與後端一致、匯出可下載
