# 99 — 行事曆：待辦、進貨付款、支出、排班與預約

> 狀態：**已採納**（2026-10-30）。需求經兩輪問答確認，§11 六題店主裁示「都照預設」（§1 第 9–14 項）。
> 決策紀錄見 `docs/adr/ADR-034-calendar-agenda-and-payments.md`；依 §10 分期實作。

## 0. 一頁看懂（給店主）

- 新增**「行事曆」**頁，有月曆、清單、單日三種看法。上面會出現：你記的待辦和事件、採購單的下單／到貨／付款、
  帳單到期、客人預約、排班。
- 首頁和開店前檢查多一塊**「今天」**：今天要做、要到貨、要付款、已過期的事。
- 採購單多了**實際下單日、預計到貨日、付款期限、付款紀錄**。付款可以分好幾次（訂金、尾款），
  月結時一筆匯款可以一次付好幾張單；每張單還欠多少一眼就看得到。
- 從**收銀抽屜**拿現金付的，系統自動記成現金支出，結帳對帳會算進去。
- 不進庫存的東西（咖啡豆、牛奶、杯子、耗材、設備、維修）記成**「支出」**；房租、水電、薪水這類固定的記成
  **「固定帳單」**，快到期會提醒。報表多一頁**「每月支出」**，可以匯出給記帳士。
- 排班、客人預約（看帳篷、估價、包場）、客人訂的貨到了提醒你通知客人：第三期。
- 每天推摘要到手機、同步到 Google 日曆：第四期，要準備的東西見 §10.4。

## 1. 店主需求與裁示（2026-10-30）

| # | 題目 | 裁示 |
|---|---|---|
| 1 | 行事曆要管哪些 | 待辦、進貨（下單、付款、到貨）、固定帳單、營業與排班、客人相關（含**預約看帳篷**）、到期與保養——全部要 |
| 2 | 進貨記在哪 | 要上架的商品**照舊走採購單**，採購單加上付款和預計到貨日；不進庫存的在行事曆記「支出」 |
| 3 | 怎麼付錢 | 四種都有：收銀抽屜拿現金、下單時就付清、月結或之後才匯款、分訂金和尾款 |
| 4 | 在哪裡看 | **先做店內看**（首頁、開店前檢查）；手機摘要、Google 日曆之後做，屆時列出要設定的東西 |
| 5 | 預約怎麼進來 | **店員手動登記**（官網預約不在本規格） |
| 6 | 排班 | **固定班別**；員工不一定要有系統帳號 |
| 7 | 月結付款 | **一筆匯款勾好幾張單**，系統分到各張單 |
| 8 | 支出報表 | 報表加**「每月支出」** |
| 9 | 採購單進價填含稅或未稅 | **照實際要付的單價（含稅）填**；對不起來的用「結清」處理 |
| 10 | 店員可否記貨到付現 | **可以**，但只限付款條件是「貨到付款」的單、只能用抽屜現金、金額不超過還欠的；作廢仍只限管理者 |
| 11 | 「取出現金」的「付小額雜支」 | **改成引導去「記一筆支出」**（第二期有支出單時一起改）；「存銀行」「補零錢」等照舊 |
| 12 | 預約看帳篷是否自動勾官網「保留中」 | **不要**：來看不等於保留，要保留店員自己勾 |
| 13 | 開店前檢查是否要待辦做完才算完成 | **不要**，只顯示 |
| 14 | 每月支出是否含收購付出、寄售撥款 | **不算進合計**，報表下方另列一行供參考 |

提出時店主沒有反對、照此辦理的預設：

- 每天都要做的事留在**開店前檢查**；行事曆只放「不是每天」的事，兩邊不重複。
- 重複規則：每週幾、每月幾號（遇到小月改月底）、每幾個月、每年。
- 待辦全店共用，可以指定負責人；打勾時記下是誰、哪天做完。
- 有金額的帳單和支出只有管理者看得到、能修改；改或刪都留稽核。
- 運費、集運費只記錄，**不攤進商品成本**（毛利報表不變）。
- 可以補填實際下單日；收據拍照、匯出給記帳士放第二期。
- 廠商可設定預設付款條件，開採購單時自動算出付款期限，可以改。
- 從抽屜付現金跟收購付現一樣要**先開帳**；自動記成現金支出，結帳應有現金會扣掉。
- 帳單和到期類的事預設**提前 3 天**出現在「快到期」，每一項都可以改。
- 預約看帳篷可以選是哪幾頂；那幾頂在 POS 上顯示「某日有人預約」，**不擋賣**。
- 預約填姓名和電話；電話跟現有會員一樣就自動連上。
- 預約時間撞在一起只提醒、不擋；公休日只顯示，不會自動關掉線上點餐。
- 客人訂的貨：採購單品項可註記「客訂：誰」，收貨時提醒要通知誰；系統不會自己傳訊息給客人。

## 2. 名詞

| 名詞 | 意思 |
|---|---|
| 待辦 | 要做的事。可以有到期日、負責人、重複規則 |
| 事件 | 不用「做完」的日子：公休、臨時店休、市集擺攤、其他 |
| 支出（支出單） | 不進庫存的訂購或花費：咖啡豆、杯子、設備、維修、帳單的某一期 |
| 固定帳單 | 會重複的支出：房租、水電、薪水……每一期自動產生一張支出單 |
| 付款 | 實際付出去的一筆錢：哪天、多少、怎麼付、付給哪幾張單 |
| 還欠多少 | 一張單的金額 − 已付（作廢的付款不算） |
| 付款期限 | 這張單最晚哪天要付 |

## 4. 待辦與事件（第一期）

### 4.1 待辦

| 欄位 | 說明 |
|---|---|
| 標題 | 必填，最多 100 字 |
| 備註 | 選填 |
| 到期日、時間 | 都選填；沒日期的放「沒有日期」清單 |
| 負責人 | 選填，從員工名單選（§4.4） |
| 重複 | 選填，規則見 §4.2 |
| 提前幾天提醒 | 預設 3 天：到期前 3 天起出現在「快到期」；0–365 |
| 只限管理者 | 勾了店員看不到（例：跟房東談續約） |
| 連結 | 選填，例：某張採購單；「前往處理」直接打開 |

- 狀態：未完成／完成（記誰、何時）／略過（重複的某一次不用做）。完成可以取消。
- 過了到期日還沒做：留在「已過期」，直到完成或略過。
- 重複的待辦**每一次都是獨立的一筆**：做完這次不影響下一次，上一次沒做也不會擋住下一次出現；
  未來的幾次在月曆上淡色顯示。改規則只影響還沒到的，已完成的不變。
- 刪除＝封存（沿用開店前檢查的做法），已完成的歷史紀錄留著。
- 店員、管理者都能新增、修改、打勾、刪除；「只限管理者」的只有管理者能看到和操作。

### 4.2 重複規則

| 規則 | 例子 | 邊界 |
|---|---|---|
| 每週 | 每週一、四叫牛奶（星期可複選） | — |
| 每月 | 每月 5 號付房租 | 29–31 號遇到沒有這天的月份 → 月底 |
| 每幾個月 | 每 2 個月的 10 號把發票交給記帳士 | 從開始的月份算起 |
| 每年 | 每年 3/1 保險續約 | 2/29 遇平年 → 2/28 |

- 可以設結束日（選填）。
- **不做「每天」**：每天的事放開店前檢查。

### 4.3 事件

- 類型：公休、臨時店休、市集／擺攤、其他。
- 全天或指定時間；可以跨好幾天（例：市集 11/8–11/9）；可以重複（例：每週一公休，規則同 §4.2）。
- 只顯示在行事曆和「今天」，**不影響 POS、線上點餐**。

### 4.4 員工名單

- 管理者維護：姓名、（選填）對應的系統帳號、停用。員工不一定要有系統帳號（裁示 6）。
- 第一期給「待辦負責人」用；第三期排班沿用同一份名單。

## 5. 採購單擴充（第一期）

### 5.1 新增欄位

| 欄位 | 說明 | 誰能改 |
|---|---|---|
| 實際下單日 | 送出時預設今天，可以選過去的日期（不能選未來）。舊單以送出時間的日期補上 | 送出的人；之後同現行規則（已下單後限管理者） |
| 預計到貨日 | 選填。分批到貨時，可改成剩下那批的日期 | **店員也能改**：這是到貨資訊，不是改單內容（廠商說會晚到，接到電話的人就能改） |
| 付款期限 | 依供應商付款條件自動帶出（§5.2）；**手動改過就不再自動改** | 管理者 |

畫面上的「下單時間」改成顯示實際下單日；原本的送出時間保留在系統裡供稽核。

### 5.2 供應商付款條件

供應商資料新增「付款條件」（選填）：

| 條件 | 付款期限怎麼算 |
|---|---|
| 先付 | ＝實際下單日 |
| 貨到付款 | ＝第一批到貨日；還沒到貨時用預計到貨日 |
| 月結（每月 X 號付上個月的） | ＝第一批到貨日所在月份的**下個月 X 號**（X 遇小月改月底）；還沒到貨時空白 |
| 到貨後 N 天 | ＝第一批到貨日 + N 天；還沒到貨時空白 |
| 沒設定 | 空白，可以手動填 |

一張單分兩個月到貨時，以第一批計算（比較早提醒），要調整就手動改。

### 5.3 還欠多少

- **應付**＝採購單金額（各品項 數量 × 進價，跟現在畫面上的合計一樣）。
  進價照實際要付給廠商的單價（含稅）填（裁示 9）。廠商少送了，照現在的做法改採購單數量，應付跟著變。
- **已付**＝有效付款分到這張單的金額合計（作廢的不算）。**還欠**＝應付 − 已付。
- 付款狀態：未付／部分付款／已付清／多付（已付 > 應付，顯示多付多少）。
- **結清**（管理者）：差一點點（尾差、廠商折讓）可以按「結清」並寫原因，這張單就不再顯示還欠；留稽核。
- 運費、集運費、關稅不算在採購單金額裡：第二期記成支出單（類別「運費關稅」），可以標「相關採購單」，
  採購單上顯示「另有運費等支出 $X」，只供參考，**不攤進商品成本**。
- 取消採購單的規則不變（只有還沒收貨才能取消）。已經付款又取消的單，付款清單上顯示
  「已取消，已付 $X，等廠商退款」；收到退款後作廢那筆付款（§6.1）。

## 6. 付款與支出

### 6.1 付款（第一期，先支援採購單）

| 欄位 | 說明 |
|---|---|
| 付款日 | 預設今天，可以選過去的日期 |
| 金額 | 正整數元 |
| 付款方式 | 收銀抽屜現金／匯款轉帳／刷卡／行動支付／其他（例：店主先墊） |
| 付給誰 | 供應商（第二期起也可以直接打名字） |
| 付到哪幾張單 | 一張或多張，各分多少 |
| 備註 | 選填，例：匯款末五碼 |

- **一張單付一次**：在採購單上按「記付款」，金額預設帶入還欠的金額。
- **訂金、尾款**：同一張單記兩次以上付款。
- **月結一次付多張**（裁示 7）：選供應商 → 列出還欠錢的單（付款期限早的在前，各張預先帶入還欠的金額）→
  勾選、可以改各張的金額 → 各張合計必須等於這筆付款 → 存檔。
- 分到某張單的金額超過它還欠的，畫面要再確認一次；存檔後那張單顯示「多付 $X」。
- **收銀抽屜現金**：必須有開帳中的班別，沒開帳就擋下並提示先開帳（CLAUDE.md §7-8）。
  存檔時自動記一筆現金異動「付款支出」，結帳應有現金扣掉這筆（§12.3）。
- **店員貨到付現**（裁示 10）：店員只能記這一種付款——付款條件是「貨到付款」的採購單、付款方式只能是
  收銀抽屜現金、一次只付一張單、金額不超過這張單還欠的。其他付款都只限管理者。
- **金額不能改**：打錯就作廢重記，金額相關一律留痕。
- **作廢**（只限管理者）：要寫原因，留稽核。抽屜現金的付款作廢時，錢放回抽屜，
  在**目前開帳中的班別**記一筆「付款作廢退回」；沒開帳要先開帳。同一筆不能作廢兩次。

### 6.2 支出單（第二期）

| 欄位 | 說明 |
|---|---|
| 類別 | §6.4 |
| 付給誰 | 選供應商或直接打名字 |
| 說明 | 例：咖啡豆 2 公斤 |
| 金額 | 正整數元；帳單金額不固定時可以先空著，付款時再填 |
| 下單日、預計到貨日、到貨日 | 都選填 |
| 付款期限 | 選填 |
| 相關採購單 | 選填（例：這張是採購單 #12 的運費） |
| 收據照片 | 選填，可多張（拍收據、匯款截圖） |

- **當場付清的小額支出**：同一個畫面建支出單並付款（例：買冰塊 200 元、抽屜現金）。
- **先訂後付、分次付**：跟採購單一樣記付款（§6.1）。
- 照片存在店裡的電腦。實作前要確認**備份有包含這些照片**，否則換電腦或還原時會遺失。
- 現金頁「取出現金」的常用原因「付小額雜支」改成引導：「要付錢買東西？改用『記一筆支出』」，
  這樣雜支才會進每月支出（裁示 11）。「存銀行」「補零錢」等搬錢的原因照舊。

### 6.3 固定帳單（第二期）

| 欄位 | 說明 |
|---|---|
| 名稱 | 例：店面房租 |
| 類別、付給誰 | |
| 預估金額 | 選填；水電這類每期不同就不填 |
| 重複規則 | 同 §4.2 |
| 提前幾天提醒 | 預設 3 天 |
| 啟用 | 停用後不再產生新的一期，已產生的保留 |

- 每一期進入提醒範圍時，自動產生該期的支出單（金額＝預估金額，可改）；付款時照實際付的填。
- 過期沒付的那一期留在「已過期」，不會因為下一期出現而消失。

### 6.4 支出類別（第二期）

預設：**進貨**（採購單的付款自動歸這類，不能手選）、食材飲料、耗材包材、設備器材、維修保養、房租、
水電瓦斯、網路電話、薪資、勞健保、記帳稅務、保險、系統與年費、運費關稅、行銷廣告、雜支。

管理者可以新增、改名、停用（用過的類別不能刪，只能停用）。

### 6.5 每月支出報表（第二期，裁示 8）

- 依**付款日**（店面時區）算到各月：月結的貨十月到、十一月付，算在十一月——這是「這個月實際付出去多少錢」。
- 依類別小計，可以點開看明細；可以匯出 Excel／CSV 給記帳士（金額存成數字，不存成文字）。
- 只算有效付款，作廢的不算。
- 收購付出、寄售撥款不算進合計（它們已有自己的報表），在報表下方另列一行供參考（裁示 14）。

## 7. 誰能做什麼

| 功能 | 店員 | 管理者 |
|---|---|---|
| 行事曆、今天 | 看（不帶金額、看不到「只限管理者」的） | 全部 |
| 待辦、事件 | 新增、修改、打勾、刪除 | 同左，另含「只限管理者」的 |
| 員工名單 | 看 | 維護 |
| 採購單實際下單日 | 同現行規則（草稿可改，已下單後限管理者） | ✓ |
| 採購單預計到貨日 | ✓ | ✓ |
| 付款期限、供應商付款條件 | — | ✓ |
| 記付款 | 只限貨到付現（裁示 10，§6.1） | ✓ |
| 作廢付款、結清 | — | ✓ |
| 支出單、固定帳單、類別、每月支出 | — | ✓ |
| 排班（第三期） | 看 | 排 |
| 客人預約（第三期） | 登記、修改 | ✓ |

**寫稽核（audit_log）**：新增付款、作廢付款、結清、改付款期限、改供應商付款條件、改帳單金額、改類別。

## 8. 「今天」（第一期）

**首頁最上方**多一塊「今天」，**開店前檢查**多一區「今天的行事曆」，內容相同：

- 待辦：今天到期、已過期、快到期（提前天數內）
- 進貨：今天預計到貨（供應商、單號）、過了預計日還沒到
- 付款（管理者）：今天到期、已逾期、快到期
- 事件：今天公休、市集等
- 門市活動：今天開始或結束的
- 寄售待撥款：N 筆（連到寄售付款）
- 第三期起：今天的預約、今天誰上班、客訂到貨待通知

開店前檢查這一區**只顯示，不影響「全部完成」**（裁示 13）。

導覽列「行事曆」旁顯示數字：今天到期＋已過期的件數，只算這個人看得到的。

## 10. 分期

每一期做完都能單獨使用。每一段：先寫測試（TDD）、本機四道門全綠、Codex 審查
（**動到金額或現金的用對抗式審查**）、有畫面就跑瀏覽器煙霧並截圖；
有 migration 的合併後寫 MacBook 升級文件。動到 migration、`shared/enums.py`、`core/*` 的依序做。

### 10.1 第一期：行事曆、待辦、採購單付款

分三段，**每一段都是後端＋畫面一起做完、合併後就能用**，依序做（都動到 migration）：

| 段 | 內容 | 審查 |
|---|---|---|
| 1A 行事曆與待辦 | `staff`、`agenda` 後端（員工名單、待辦、事件、重複規則、封存、彙整、今天）；行事曆頁、待辦與事件視窗、員工名單；首頁「今天」、開店前檢查、導覽列數字；帶入門市活動起訖與寄售待撥款筆數 | 一般 |
| 1B 採購單日期 | `purchasing` 擴充（實際下單日、預計到貨日、供應商付款條件、付款期限）與畫面；行事曆與「今天」帶入下單、預計到貨、到貨、逾期未到 | 一般 |
| 1C 採購單付款 | `expenses` 付款與分配（先支援採購單）、結清、作廢；`cashdrawer` 兩種新現金異動、應有現金、現金報表；採購單記付款、月結付款、還欠多少、店員貨到付現；行事曆與「今天」帶入付款與付款期限 | **對抗式**（金額、現金） |

### 10.2 第二期：支出、固定帳單、每月支出報表

支出單、收據照片、固定帳單、支出類別、每月支出報表與匯出；月結付款可以同時勾支出單。

### 10.3 第三期：排班、客人預約、客訂到貨提醒

- **排班**：管理者設班別（名稱、幾點到幾點）；週排班表（員工 × 日期）選班別；請假（事假、病假、特休、其他＋備註）；
  **「複製上週」**一鍵帶入；店員可以看。
- **客人預約**：類型（看帳篷、收購估價、包場、其他）、日期時間、時長（預設 60 分鐘）、客人姓名與電話
  （電話跟會員一樣就自動連上）、人數（包場）、要看的帳篷（從在庫寄售品選，可多頂）、接待的員工、
  狀態（預約中、已到、沒來、取消）、備註。時間重疊只提醒。
  POS 結帳掃到有預約的帳篷，在結帳前的備註確認視窗多一行「11/2 14:00 有客人預約看這頂，賣之前請先確認」，
  可以照賣（沿用寄售帳篷「保留中」的提醒做法，docs/97 §6）。預約**不會**自動勾官網「保留中」（裁示 12）。
- **客訂到貨**：採購單品項可填「客訂：誰、電話」；那一項收貨後，「今天」出現「客訂到貨：通知王小姐」，
  按「已通知」就消失。系統不會自己傳訊息。

### 10.4 第四期：手機每日摘要、Google 日曆同步（裁示 4）

做到時再一步一步帶店主設定；先列出大概要準備的東西：

- **每天推摘要到手機**：每天早上一則「今天要做／要到貨／要付款／已過期」。
  - Email：一個寄信用的信箱（例：店裡專用的 Gmail 開「應用程式密碼」），加上要收的信箱。最簡單。
  - LINE：店家的 LINE 官方帳號＋開通 Messaging API；收訊的人要加好友，並經雲端取得收訊人的 ID
    （店裡電腦在內網，收不到 LINE 的通知，要用現有的雲端轉）。免費方案每月訊息則數有上限。
- **同步到 Google 日曆**：一個 Google 帳號與一個專用日曆（例：「露坑店務」），
  在 Google Cloud 建一個服務帳號並把日曆分享給它。系統單向送出，**預設不送金額**。
  金鑰檔放店裡電腦的設定檔，不進 repo。

## 11. 店主確認的六題（2026-10-30：都照預設）

裁示內容已寫進 §1 第 9–14 項；這裡留下當時的考量。

1. **進價填含稅還是未稅**：影響「還欠多少」。若填未稅、廠商另收 5% 稅，每張單付完都會顯示「多付」。
2. **店員貨到付現**：現在「取出現金」只有管理者能用，店員一個人在店時沒辦法記付給司機的錢。
3. **「付小額雜支」**：不改的話，雜支不會出現在每月支出報表。第二期有支出單時一起改。
4. **預約與「保留中」**：來看不等於保留。
5. **開店前檢查**：只顯示，不讓待辦擋住開店。
6. **每月支出的範圍**：收購付出、寄售撥款已有自己的報表，算進合計會跟毛利報表口徑混在一起。

## 12. 技術設計（給實作者）

### 12.1 模組與依賴

依賴一律單向、只經對方的 service（CLAUDE.md §2）。**purchasing 不依賴 expenses／agenda**，避免循環：
採購頁要顯示的付款資訊由前端另外呼叫 expenses 的 API 組合。

| 模組 | 內容 | 依賴 |
|---|---|---|
| `staff`（新） | 員工名單；第三期加班別、排班、請假 | user（選填對應帳號） |
| `agenda`（新） | 待辦、事件、重複規則、行事曆彙整、今天 | staff、purchasing、expenses、campaigns、consignment；第三期加 appointments |
| `expenses`（新） | 付款、分配、結清；第二期加支出單、固定帳單、類別、每月支出資料 | purchasing（驗證採購單、取金額與供應商）、cashdrawer（記現金異動） |
| `purchasing`（擴充） | 實際下單日、預計到貨日、付款期限、供應商付款條件；第三期加客訂註記 | 不變 |
| `cashdrawer`（擴充） | 新現金異動類型、應有現金公式、現金報表 | 不變 |
| `reports`（擴充，第二期） | 每月支出頁與匯出 | expenses |
| `appointments`（新，第三期） | 客人預約 | inventory、contacts、staff |

### 12.2 資料表（草案，實作時以 migration 為準）

所有表都有 `store_id`（CLAUDE.md §4）；金額一律 `Numeric(12,0)` → `Decimal`（§6）。

- `staff_members`：`name`、`user_id`（可空）、`is_active`。
- `agenda_task_series`：重複待辦的規則——`title`、`note`、`assignee_staff_id`、`manager_only`、`link_href`、
  `rule_kind`（WEEKLY／MONTHLY／EVERY_N_MONTHS／YEARLY）、`weekdays`（int[]）、`day_of_month`、`interval_months`、
  `month_of_year`、`starts_on`、`ends_on`、`lead_days`、`archived_at`。
- `agenda_tasks`：每一筆待辦（單次的，或重複規則的某一次）——同上的顯示欄位、`due_on`、`due_time`、`lead_days`、
  `series_id`＋`occurrence_on`（**唯一**：同一規則同一天只有一筆）、`status`（OPEN／DONE／SKIPPED）、
  `done_at`、`done_by`、`archived_at`、`created_by`。重複規則的某一次在被打勾、略過或修改時才建列；
  未建列的過去日期視為「已過期」，未來的只在彙整時算出來顯示。
- `agenda_events`：`kind`（CLOSED／TEMP_CLOSED／MARKET／OTHER）、`title`、`note`、`starts_on`、`ends_on`、
  `start_time`、`end_time`、`manager_only`、重複規則欄位（同上）、`archived_at`。
- `purchase_orders` 加：`ordered_on`（date；migration 以 `ordered_at` 的店面日期回填）、`expected_on`、
  `payment_due_on`、`payment_due_manual`（bool）。
- `suppliers` 加：`payment_terms`（PREPAID／COD／MONTHLY／NET_DAYS，可空）、`payment_terms_value`
  （月結的 X 號或 N 天）。
- `payments`：`paid_on`、`amount`（> 0）、`method`（CASH_DRAWER／TRANSFER／CARD／MOBILE／OTHER）、
  `supplier_id`（可空）、`payee_name`（快照）、`note`、`cash_movement_id`（可空、唯一）、
  `voided_at`、`voided_by`、`void_reason`、`void_cash_movement_id`、`created_by`、`idempotency_key`＋`request_fingerprint`。
- `payment_allocations`：`payment_id`、`purchase_order_id`（可空）、`expense_item_id`（可空，第二期）、`amount`（> 0）；
  CHECK 恰好指向一種單。
- `payable_settlements`（結清）：`purchase_order_id`／`expense_item_id`、`written_off_amount`、`reason`、`created_by`。
- 第二期：`expense_categories`（`name`、`system_code`：PURCHASE＝進貨、`is_active`、`sort_order`）、
  `expense_items`、`expense_item_photos`、`bills`。
- 第三期：`shift_types`、`shifts`、`staff_leaves`、`appointments`、`appointment_items`；
  `purchase_order_lines` 加 `customer_note`、`customer_notified_at`。

列舉值放 `shared/enums.py`；新增 `CashMovementType.EXPENSE_PAYMENT_OUT`（付款支出）、
`EXPENSE_PAYMENT_VOID_IN`（付款作廢退回），`ref_type="payment"`。

### 12.3 不變量（要用測試守護）

1. 有效付款的分配合計＝付款金額；每筆分配恰好指向一張單；分到的單必須同店、未取消、與付款的供應商相同。
2. 抽屜現金付款必須在開帳中的班別；建立**恰好一筆** `EXPENSE_PAYMENT_OUT`。作廢建立**恰好一筆**
   `EXPENSE_PAYMENT_VOID_IN`，記在作廢當下開帳中的班別；同一筆不能作廢兩次。
3. 結帳應有現金 ＝ 開帳零用金 ＋ Σ(SALE_IN, ACQUISITION_VOID_IN, **EXPENSE_PAYMENT_VOID_IN**)
   − Σ(BUYOUT_OUT, CONSIGNMENT_PAYOUT_OUT, SALE_REFUND_OUT, **EXPENSE_PAYMENT_OUT**) ± ΣMANUAL_ADJUST。
   `expected_amount` 遇未知類型仍拒絕；現金報表各類型都列出。合併時同步更新 CLAUDE.md §7-4 的公式文字。
4. 已付＝有效付款分配合計；還欠＝應付 − 已付 − 結清金額；每月支出只算有效付款、依店面時區的付款日。
5. 重複規則：29–31 號在小月落到月底；2/29 在平年落到 2/28；每 N 個月從開始月份起算；
   改規則不改已完成或已略過的那幾次。
6. 付款期限依付款條件計算；`payment_due_manual` 為真時不再自動覆寫。
7. 新增付款帶 Idempotency-Key：網路重送不會重複付款、不會重複扣抽屜（沿用收貨與現金異動的做法）。
8. 店員從任何 API（含彙整、今天）都拿不到付款金額與「只限管理者」的項目。
9. 店員記付款只能是：抽屜現金、單一採購單、該單付款條件為貨到付款、金額 ≤ 還欠；其餘一律拒絕（裁示 10）。

### 12.4 API（草案，`operation_id` 實作時定）

- `GET /agenda?from=&to=&types=`：彙整；`GET /agenda/today`：今天＋導覽列數字。
- `/agenda/tasks`、`/agenda/task-series`、`/agenda/events`：新增、修改、封存；
  `POST /agenda/tasks/{id}/done|skip|reopen`（重複規則的某一次用 `series_id`＋`occurrence_on` 指定）。
- `/staff-members`：清單、新增、修改、停用。
- `PATCH /purchase-orders/{id}/schedule`：實際下單日、預計到貨日、付款期限（各自的權限見 §7）。
- `PATCH /suppliers/{id}`：加付款條件欄位。
- `GET /expenses/payables?supplier_id=`：還欠錢的單（付款期限早的在前）。
- `GET /expenses/purchase-order-balances?ids=`：採購頁顯示應付、已付、還欠、狀態。
- `POST /expenses/payments`（Idempotency-Key）、`GET /expenses/payments?from=&to=`、`POST /expenses/payments/{id}/void`。
- `POST /expenses/settlements`。

### 12.5 測試

- 單元：重複規則（含月底、閏年）、付款期限、分配驗證、應有現金新類型。
- 整合：各端點、權限（店員拿不到金額與只限管理者的項目）、跨店隔離、冪等重送。
- 端對端：貨到付現（開帳 → 付款 → 結帳應有現金）、月結一筆付三張、作廢付現退回抽屜、沒開帳付現被擋。
- 瀏覽器煙霧（docs/20）：`frontend/scripts/calendar-smoke.mjs`、`frontend/scripts/purchasing-payments-smoke.mjs`。
