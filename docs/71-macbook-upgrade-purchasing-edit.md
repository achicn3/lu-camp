## 3. 驗證（每一項都回報結果）

1. docs/43 §4 開頭的 `curl`／`launchctl` 檢查：三個 `state` 都是 `running`、兩個 http 都是 `200`。
2. 舊發票有搬過去：升級前後各跑一次，數字要相同（升級前是收貨上的發票張數，升級後是新表張數）：
   ```bash
   # 升級前
   psql "$DATABASE_URL" -Atc "SELECT count(*) FROM goods_receipts WHERE invoice_number IS NOT NULL"
   # 升級後
   psql "$DATABASE_URL" -Atc "SELECT count(*) FROM purchase_input_invoices"
   ```
   （`DATABASE_URL` 去掉 `+asyncpg` 再給 psql。）
3. 請**店主**打開「採購 / 補貨」→「進項發票」分頁：看得到以前登過的發票。

## 4. 出問題怎麼退

- 只退程式：`git checkout <記下的 commit>`，再照 docs/43 §6 重 build 前端、`install-launchd.sh`。
  **注意：這次舊程式讀不懂新的發票結構**，只退程式時採購單明細會讀不到發票——要一起降資料庫（下一點）。
- 降版：`uv run alembic downgrade d5f1b3c7e9a2`。只有在**每張發票都恰好對到一批收貨**、而且**沒有採購更正的庫存異動**時才降得下去；
  已經用新功能合併登錄過發票、或改過已收貨的採購單，降版會拒絕——那時就停下來找店主，不要硬降。
